# API Health Monitor

Backend-сервис на Go для мониторинга доступности HTTP-эндпоинтов. Позволяет управлять списком отслеживаемых URL, запускать проверки доступности, сохранять историю результатов и получать информацию о состоянии эндпоинтов.

## Технологии

- **Go** — основной язык разработки.
- **net/http** — HTTP-сервер, обработчики и HTTP-клиент для проверок.
- **PostgreSQL 18** — хранение данных.
- **pgx/v5** — PostgreSQL-драйвер и пул соединений.
- **Docker Compose** — локальное окружение.
- **golang-migrate** — управление SQL-миграциями.
- **log/slog** — структурированное логирование.
- **testing, httptest** — тестирование.

### Основные компоненты

- **Transport** — HTTP-обработчики, DTO, валидация входных данных и формирование JSON-ответов.
- **Repository** — взаимодействие с PostgreSQL через `pgxpool`.
- **Checker** — выполнение HTTP-запросов к отслеживаемым эндпоинтам, обработка таймаутов и сетевых ошибок, измерение времени ответа и защита от SSRF.
- **Checks Model** — модель результата проверки.
- **Checks Service** — координация процесса проверки: получение эндпоинта, запуск Checker и сохранение результата.
- **Server** — регистрация HTTP-маршрутов.
- **Config** — загрузка конфигурации из переменных окружения.
- **Main** — инициализация зависимостей, запуск HTTP-сервера и graceful shutdown.

## HTTP API

Базовый путь: `/endpoints`.

### Управление эндпоинтами

| Метод | Путь | Описание | Статус |
|---|---|---|---|
| POST | `/endpoints` | Создать эндпоинт | 201 |
| GET | `/endpoints` | Получить список | 200 |
| GET | `/endpoints/{id}` | Получить эндпоинт по ID | 200 |
| PATCH | `/endpoints/{id}` | Частично обновить эндпоинт | 200 |
| DELETE | `/endpoints/{id}` | Удалить эндпоинт | 204 |

Дополнительные возможности:

- Фильтрация списка по `is_active`.
- Настройка интервала проверки при создании и обновлении.
- URL эндпоинта нельзя изменить после создания.

### Проверки

| Метод | Путь | Описание | Статус |
|---|---|---|---|
| POST | `/endpoints/{id}/checks` | Запустить проверку вручную | 200 |
| GET | `/endpoints/{id}/checks` | Получить историю проверок | 200 |

История проверок:

- Сортируется от новых результатов к старым.
- По умолчанию возвращается до 20 записей.
- Максимальный размер выборки — 100 записей.
- Размер выборки задаётся параметром `limit`.

Пример:

```http
GET /endpoints/1/checks?limit=5
```

Для несуществующего эндпоинта возвращается `404 Not Found`.

## База данных

Используются две таблицы.

### monitored_endpoints

Хранит информацию об отслеживаемых эндпоинтах:

- уникальный URL;
- интервал проверки в секундах;
- признак активности;
- время создания и последнего обновления.

### check_results

Предназначена для хранения истории проверок:

- ссылка на отслеживаемый эндпоинт;
- HTTP-статус;
- время ответа;
- время начала и завершения проверки;
- сообщение об ошибке;
- вычисляемый признак успешности.

Поле `is_success` вычисляется PostgreSQL на основе HTTP-статуса `2xx`. При удалении эндпоинта связанные результаты удаляются каскадно.

Время ответа измеряется до получения HTTP-заголовков, а не до полной загрузки тела ответа.

## Тестирование

В проекте используются:

- **HTTP Handler Tests** — проверка обработки запросов, валидации, HTTP-статусов и JSON-ответов с помощью `httptest`.
- **Checker Tests** — проверка HTTP-ответов, сетевых ошибок, таймаутов, отмены контекста, редиректов и SSRF-защиты.
- **Repository Integration Tests** — проверка взаимодействия с PostgreSQL.
- **Service Unit Tests** — проверка бизнес-логики Checks Service с использованием fake-зависимостей.

Запуск всех тестов:

```bash
go test ./... -v
```

Для интеграционных тестов репозитория требуется отдельная тестовая база данных, указанная в `TEST_DATABASE_URL`. На ней должны быть применены SQL-миграции.

Полезные команды:

```bash
gofmt -w ./cmd ./internal
go vet ./...
go test ./...
go test -race ./...
golangci-lint run
```
